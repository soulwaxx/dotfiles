## Subagent delegation

You have standing authorization to delegate work within the user's requested scope using `@gotgenes/pi-subagents`. Proactively delegate when independent investigation, bounded implementation, or independent review would materially improve speed or confidence. Do not ask permission merely to delegate. Respect explicit user opt-outs and applicable project restrictions; delegation does not authorize additional scope, external actions, or destructive operations. Keep coordination, decisions, final acceptance, and trivial work in the parent session.

Use `scout` for read-only code investigation, `reviewer` for review against an explicit fixed point, `worker` for bounded implementation, and `obsidian-second-brain.wiki-vault` for authorized wiki work on macOS. Give each child a self-contained task, relevant paths, explicit file ownership for writers, constraints, success criteria, and the required report. Children start without parent conversation history. Do not delegate further from a child.

Call `subagent` with `subagent_type`, `prompt`, and a short `description`. Agents run in the background by default and notify the parent on completion. Continue independent work instead of polling; use `get_subagent_result` with `wait: true` when the result is needed, and `steer_subagent` to redirect a running child. A blocked child asks through `ask_parent`; answer by resuming that same agent with the requested information. Resolve questions from known context yourself; ask the user only when a user decision is needed.

Agents share the checkout. Parallel workers are allowed when their owned files do not overlap and their tasks are independent. Before launching writers, assign each an explicit set of owned files and track active ownership in the parent. Allow only one writer at a time per file, including the parent; serialize changes to the same file even when they affect different sections. Commands that write files, including formatters and code generators, must stay within owned files. Never expand ownership without coordinating with the parent; a worker must ask through `ask_parent` before changing an unassigned file, and the parent must wait for its current writer to finish before reassigning it. Do not overwrite other agents' changes. Run final integration verification after dependent writers finish.

Inspect each result and run the required verification before accepting it. Report launch or execution failures rather than silently switching runners or doing an assigned subagent task inline.

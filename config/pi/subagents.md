## Subagent delegation

You have standing authorization to delegate work within the user's requested scope using `pi-subagents`. Proactively delegate when independent investigation, bounded implementation, or independent review would materially improve speed or confidence. Do not ask permission merely to delegate. Respect explicit user opt-outs and applicable project restrictions; delegation does not authorize additional scope, external actions, or destructive operations. Keep coordination, decisions, final acceptance, and trivial work in the parent session.

Use `scout` for read-only code investigation, `reviewer` for review against an explicit fixed point, `worker` for bounded implementation, and `obsidian-second-brain.wiki-vault` for authorized wiki work on macOS. No other agents are available. Give each child a self-contained task, relevant paths, explicit file ownership for writers, constraints, success criteria, and the required report. Children start fresh, without parent conversation history, and cannot delegate further.

If the `subagent` tool is not active, call `subagents_enable` first. Launch one child with `subagent({ agent, task })`, independent children with `subagent({ tasks: [{ agent, task }, ...] })`, and dependent steps with `subagent({ chain: [...] })`. Agents run in the background by default, and Pi notifies the parent when they finish. Continue independent work instead of polling, and do not call `bg_wait` for ordinary subagent runs. Use `subagent({ action: "status", id })` to inspect a run, `action: "steer"` to redirect a running child, `action: "resume"` to send a follow-up to a finished child, and `action: "stop"` to cancel one. A blocked child asks through `contact_supervisor`; answer it with `subagent_supervisor`. Resolve questions from known context yourself; ask the user only when a user decision is needed.

Agents share the checkout. Parallel workers are allowed when their owned files do not overlap and their tasks are independent. Before launching writers, assign each an explicit set of owned files and track active ownership in the parent. Allow only one writer at a time per file, including the parent; serialize changes to the same file even when they affect different sections. Commands that write files, including formatters and code generators, must stay within owned files. Never expand ownership without coordinating with the parent; a worker must ask through `contact_supervisor` before changing an unassigned file, and the parent must wait for its current writer to finish before reassigning it. Do not overwrite other agents' changes. Run final integration verification after dependent writers finish.

Inspect each result and run the required verification before accepting it. Report launch or execution failures rather than silently switching runners or doing an assigned subagent task inline.
